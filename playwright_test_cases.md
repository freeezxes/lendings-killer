# Автоматизированное E2E тестирование (Playwright) — Test Cases

Этот документ описывает ключевые сценарии (test cases) для проверки работоспособности платформы `lendings.kz` (dum-e.com). AI-агенты могут использовать этот файл как инструкцию для написания и выполнения E2E-тестов через Playwright.

---

## Подготовка окружения
Перед запуском тестов агент должен активировать виртуальное окружение, в котором установлен Playwright:
```bash
source venv_playwright/bin/activate
# Запуск тестов: python <имя_файла.py>
```

---

## 🧪 Сценарий 1: Регистрация и получение бесплатных кредитов (Promo)

**Цель:** Проверить, что пользователь может войти/зарегистрироваться и использовать секретный промокод для пополнения баланса без оплаты.

**Шаги в Playwright:**
1. Открыть `https://dum-e.com/auth`
2. Найти форму авторизации.
3. Ввести тестовый номер телефона (например, `77770000001`) и пароль.
4. Нажать кнопку "Войти / Зарегистрироваться" и дождаться `page.wait_for_url("**/dashboard")`.
5. На дашборде нажать на кнопку "Купить слот" или пополнения баланса (переход на `/payment?reason=...`).
6. На странице оплаты нажать на скрытую кнопку ввода промокода или сразу перейти по прямой ссылке, если она реализована в UI (либо перехватить запрос оплаты и отправить POST-запрос с промокодом `test67`).
7. Убедиться, что в UI дашборда увеличилось количество `site_slots` и `dev_credits`.

## 🧪 Сценарий 2: Полный цикл создания сайта (Onboarding)

**Цель:** Проверить чат-онбординг, загрузку изображений и успешную генерацию нового лендинга.

**Шаги в Playwright:**
1. Авторизоваться под тестовым аккаунтом (у которого есть свободные слоты и кредиты).
2. Перейти на `https://dum-e.com/dashboard/create` (или кликнуть "＋ Create Page").
3. Дождаться появления поля ввода чата `#chatInput`.
4. Вместо пошаговых ответов, отправить ИИ один объемный промпт со всеми данными:
   ```python
   prompt = "Привет! Я Иван, делаю мужские стрижки в Астане. Услуги: стрижка 5000, борода 3000. Номер WhatsApp: +7 777 123 4567. Сделай сайт в брутальном темном стиле."
   page.fill('#chatInput', prompt)
   ```
5. Загрузить тестовое фото через скрытый инпут загрузки фотографий (`#photoInput`).
   ```python
   page.set_input_files('#photoInput', 'test_photo.jpg')
   page.wait_for_selector('.photo-preview') # Ждем превью
   ```
6. Нажать кнопку отправки сообщения.
7. Дождаться ответа от ИИ. Если всё ок, должна появиться кнопка «Да, создать сайт» (или аналогичная кнопка подтверждения).
8. Кликнуть кнопку запуска генерации.
9. Дождаться автоматического редиректа на дашборд готового сайта (рабочую панель).
   ```python
   # Ожидаем редирект в рабочую область после статуса "completed"
   page.wait_for_url("**/dashboard/sites/*", timeout=120000)
   ```
10. Извлечь URL сгенерированного сайта из `iframe.preview-frame`.
11. Сделать скриншот готового сайта для визуальной валидации.

## 🧪 Сценарий 3: AI-Редактирование готового сайта (Workspace Chat)

**Цель:** Проверить, что готовый сайт можно изменить с помощью чата редактирования, не сломав при этом его базовую структуру.

**Шаги в Playwright:**
1. Открыть `https://dum-e.com/dashboard/sites/{site_id}`.
2. Убедиться, что в правой части экрана доступен инпут редактирования (`#siteEditInput`).
3. Ввести промпт на изменение, заставляющий ИИ сразу применить изменения (чтобы пропустить уточняющие вопросы):
   ```python
   edit_prompt = "Добавь блок с отзывами клиентов. Отзыв 1: 'Отличный мастер!' - Алексей. Примени изменения сразу, подтверждаю, без лишних вопросов."
   page.fill('#siteEditInput', edit_prompt)
   page.click('button:has-text("Send")')
   ```
4. Дождаться перезагрузки рабочей области:
   ```python
   page.wait_for_timeout(45000) # Даем время на генерацию 
   page.wait_for_load_state("networkidle")
   ```
5. Сделать скриншот обновленного `iframe` и сравнить с изначальным скриншотом.
6. Открыть публичную ссылку сайта (`https://dum-e.com/site/{slug}`) и убедиться, что изменения действительно применились.

## 🧪 Сценарий 4: Ограничения и защита от спама (Validation)

**Цель:** Проверить, что ИИ корректно блокирует запрещенные тематики и не тратит кредиты пользователя впустую.

**Шаги в Playwright:**
1. Зайти в `/dashboard/create`.
2. Написать запрещенный промпт: *"Сделай мне сайт для онлайн казино и ставок на спорт"*.
3. Дождаться ответа ИИ.
4. Спарсить ответ и убедиться, что ИИ отказывается создавать сайт (содержит слова вроде "отказываюсь", "не могу", "запрещено" и не выдает кнопку "Создать сайт").
5. Проверить баланс `dev_credits` — он **не должен** списаться за генерацию сайта (списывается только за чат, если это настроено).

## 🤖 Как AI-Агенту автоматизировать эти проверки?

Если ты (AI-Агент) получил задачу *"проверь функционал создания сайта"*, используй следующий шаблон Playwright-скрипта:

```python
from playwright.sync_api import sync_playwright
import time

def run_tests():
    with sync_playwright() as p:
        browser = p.chromium.launch(headless=True)
        page = browser.new_page()
        
        # 1. Авторизация
        page.goto("https://dum-e.com/auth")
        # ... заполнение логина ...
        
        # 2. Инъекция кредитов (если доступен бэкенд)
        # Лучше всего пополнять через промокоды или напрямую в БД:
        # import sqlite3; ... UPDATE users SET site_slots = 5 WHERE ...
        
        # 3. Переход в создание и отправка запроса
        page.goto("https://dum-e.com/dashboard/create")
        page.fill('#chatInput', 'Текст промпта...')
        page.set_input_files('#photoInput', 'photo.jpg')
        page.click('button.send-btn')
        
        # Ожидание кнопки и клик
        page.wait_for_selector('button:has-text("Да, создать сайт")')
        page.click('button:has-text("Да, создать сайт")')
        
        # 4. Ожидание результата
        page.wait_for_url("**/dashboard/sites/*", timeout=150000)
        
        print("Test Passed: Site Created Successfully")
        browser.close()

if __name__ == "__main__":
    run_tests()
```

**Рекомендации для AI:**
- Сохраняй скриншоты при падениях таймаута: `page.screenshot(path="error_state.png")`.
- Логируй каждый шаг в `print()`, чтобы в случае зависания таски в фоне, можно было прочитать `.log` файл и понять на каком этапе сломался тест.
- Не используй жесткие таймауты вроде `time.sleep(10)`, опирайся на состояния UI: `page.wait_for_selector(...)` или `page.wait_for_load_state('networkidle')`.
